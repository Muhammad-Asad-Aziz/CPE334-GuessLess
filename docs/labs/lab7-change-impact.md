## 2. Change Summary & Closed-World Scope Guardrails

1. **Creation & Validation (`FR-01`, `F-02`):** `POST /api/v1/surveys` accepts optional nullable `maxResponses` (`null` or omitted = unlimited; when provided, integer `1–1000`). Out-of-range or non-integer values (`0`, `-1`, `1001`, `2.5`, non-numeric) return `400 VALIDATION_ERROR` naming `maxResponses`. Stored via backward-compatible expand-only migration `0003_add_survey_max_responses` (`Survey.maxResponses Int?` + `survey_max_responses_chk`).
2. **Submission & Concurrency-Safe Auto-Closure (`FR-03`, `FR-08`, `FR-11`, `BR-02`, `BR-04`, `NFR-06`, `F-03`):** Inside `ResponseService.submitResponse`, acquire a row lock on the target `Survey` via parameterized raw SQL (`SELECT id FROM "Survey" WHERE id = $1::uuid FOR UPDATE`) before status/count checks, preserving existing check ordering (`DRAFT` → `404`, `CLOSED` → `409 SURVEY_NOT_OPEN`, existing `Participation` → `409 DUPLICATE_RESPONSE`, `validateAnswers` → `400 VALIDATION_ERROR`). After inserting `Participation`, `Response`, `Answer`, and `AnswerSelection`, if `survey.maxResponses !== null`, count stored responses in the same transaction; if `count >= survey.maxResponses`, atomically update `Survey` setting `status = 'CLOSED'` and `closedAt = now`.
3. **API Payloads & UI (`F-02`, `F-03`, `F-04`):** Owner endpoints (`POST /surveys`, `GET /surveys`, `GET /surveys/:id`, `POST /surveys/:id/publish`, `POST /surveys/:id/close`, `GET /surveys/:id/summary`) and respondent endpoints (`GET /available-surveys`, `GET /available-surveys/:id`) include `maxResponses: number | null`. UI screens add `"Response limit (optional, 1–1000)"` on `/my-surveys/new`, `responseCount / maxResponses` or `"Unlimited"` on `/my-surveys` & `/my-surveys/:surveyId`, `"Limit: N responses"` badge on `/available` & `/available/:surveyId`, and `"Total responses: N / M"` (or `"Total responses: N"` when unlimited) on `/my-surveys/:surveyId/summary`.
4. **Closed-World Exclusions:** No new endpoints, no Sprint 2/3 features (`F-05`–`F-09`), no changes to `F-01` auth/token/role guards, and no changes to `BR-04` incomplete draft publish checks or `maxResponses = null` unlimited survey behavior.
